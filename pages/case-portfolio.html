03. CASE STUDY

ポートフォリオ
再定義と再構成

プロジェクト : 採用者の採用評価を仮定し、仮説に則ってポートフォリオを再設計

担当範囲 : 情報設計 / UX設計 / UI設計 / 構成再定義 / 実装 / 改善

概要

転職活動において、計画・仮説 → 実行 → 評価 → 改善のプロセスを迅速かつ継続的に実施。 段階を踏んでアプローチを切り替えてみたが、改善が十分に実現できていなかった。
そこで、転職活動を通して見てきた100社近い各企業の募集要項から、採用側の不安や評価観点を観察・整理し、 評価基準を仮説立てしてポートフォリオの構成を再定義した。
本ページはポートフォリオ改善の流れだけでなく「どのように課題を捉え、どのように判断し、構造に落としたか」 という一連のプロセスを踏まえた事例である。

01. OVERVIEW

TARGET USER

主な対象は、SaaS企業の採用担当者、 UX / プロダクトデザイナー、マネージャーなどの現場メンバー。 あわせて、エージェント担当や書類スクリーニング担当も想定している。

CORE GOAL

書類通過率を安定して改善し、 UX / UI・プロダクトデザイナー職の面接に進める状態をつくること。 そのために、採用側が短時間で「任せられる」と 判断しやすい構造へ見直すことを目的とした。

MY APPROACH

問題を単なるポートフォリオ更新ではなく、 採用側の不安を解消するための 情報設計と希望職種のポジショニングの調整として捉えた。 そのため、各企業の募集要項から採用者の評価基準を仮説立てし、構造から見直す方針で改善を進めた。
それを踏まえたサイト訪問時の第一印象となるTOPの再構成、各制作物の思考プロセス、 SaaS自主制作の位置づけまで含めて、全体構造から見直している。

02. PROBLEM

■ 採用側の3つの不安に対して「任せられる根拠」が十分に伝わっていなかった

100社近い各企業の募集要項を整理した結果、 採用側が気にする点はおおまかに分けて、以下の3つにあると仮説立てた。
① SaaS / プロダクト経験がなくても任せられるか
② 改善プロセスに再現性があるか
③ チーム開発の前提で動けるか
 これらを仮定した際、旧ポートフォリオでは、この3つの評価に対する判断材料が構造として見えにくかった。

■ WEBデザイナー / 通販運用寄りに見え、希望職種との見え方にズレがあった

実務経験の見せ方や事例の並び方によって、 UIを作る人・通販事業の運用を回す人という印象が先に立ちやすく、 課題設定や構造設計、改善の結果分析による仮説立てまで行っていることが伝わりにくかった。
そうした状況であったため、希望職種である、UX / UI・プロダクトデザイナーとしての見え方につながりにくかった。

■ SaaS自主制作が補足的に見え、実務経験からの課題制作として見えていなかった

希望職種との距離を埋めるために制作したSaaS事例も、 位置づけが弱いままでは単なるアピールとしての自主課題として見られやすい状態だった。
本来は、実務経験を踏まえたユーザー視点から課題を抽出し、 プロダクトとしての価値を整理した成果物である。 しかし、十分にその説明やプロセスを伝えることができておらず、 その意図が評価につながりにくかった。

■ 採用側の評価項目に対して、ポートフォリオ全体の構造が最適化されていなかった

多忙な採用担当者は、担当範囲、課題設定力、要件整理、構造設計、プロダクト理解、アウトプット品質までを短時間で見ている。
しかし従来の私のポートフォリオの構成では、それらを読み取るためには解釈が必要であり、第一印象と判断スピードの面でも不利になっていた。

03. THE INSIGHT

足りなかったのは、
“任せられる根拠の伝え方” だった。

本取り組みを通して、価値は情報量ではなく、 評価の基準と構造の整合によって決まると捉え直した。
スキル・実績・応用といった要素を個別に追加しても、 それぞれが評価の軸と一致していなければ、 意図した価値としては伝わらない。
そのため、情報の内容だけでなく 「誰が・何を基準に・どのように判断するか」を前提に、 構造そのものを設計対象として扱う必要があると考えた。

04. STRATEGIC DECISION

01. PROJECT START

出発点は、評価につながりにくい状況が続いていたことだった

制作物や経験はあるにもかかわらず、 書類選考の段階で評価につながりにくい状況が続いていた。
要因を整理すると、希望職種とのポジショニングのズレ、 制作物の説明不足、採用側の評価基準に沿っていない構成など、 複数の課題が重なっている状態だった。

02. REFRAMING THE ISSUE

制作物・実績・自主制作と試行しても、問題は全体構造にあると分かった

改善は、段階的な検証プロセスとして進めた。 試行ごとに見え方は変わったが、 個別対応では採用側の評価観点とのズレを解消しきれなかった。

STEP 1

制作物一覧として作成

まずは「どんなことができるか」という視点から、 制作物を一覧的に配置した。 スキルの幅は伝えやすくなったが、 UX / UI・プロダクトデザイナーとして任せられる判断材料にはなりにくかった。

↓

STEP 2

実績ベースで再構成

次に「どんなことをしてきたか」「どんな課題に取り組んだか」という視点から、 実績や成果を補足する構成へ切り替えた。 経験の裏付けは強化できたが、 課題設定や構造設計のプロセスまでは十分に伝わらなかった。

↓

STEP 3

SaaS自主制作を追加

さらに、自主制作を通じて応用力の表現を試みた。 希望職種との距離は埋められたが、 既存構造のままでは補足的な事例として見えやすく、 思考のプロセスまで伝えるには不十分だった。

これらの試行を通して、 制作物や実績を追加しても 「どのように考え、どう判断しているか」が ポートフォリオ全体を通して十分に伝わっていないと分かった。

03. DECISION MAKING

複数の改善案を比較し、構造から見直す“再定義案”の方針を選択した

制作物の整理や追加ではなく、 評価基準に対してどう伝わるかを踏まえ、 構造から見直す方針とした。

一覧強化案

既存の制作物や実績を整理し、見せ方を最適化する

Pros: 工数が少なく短期間で整えられる

Cons: 思考プロセスなどの情報拡充がないままのため、評価基準とのズレやポジショニングは解消しにくい

再定義案

ポートフォリオサイト全体を再定義し、構造から見直す

Pros: 評価基準に合わせた構成にすることができるため、採用側の理解が深まる

Cons: ポートフォリオサイトの構造整理と、各プロダクトの意図の説明が必要となるため大掛かりな工程が必要

追加制作案

新規制作を追加し、事例数で補完する

Pros: 希望職種に合わせた事例数を増やし、経験の幅を補強できる

Cons: 意図を伝えるための構造がそのまま変わらなければ、採用側への伝わり方は変わりにくい

一覧強化案はスキルの幅や経験を見せることには有効だったが、 採用側が知りたい「どのように考え、どう判断しているか」までは伝えきれないと考えた。
追加制作案は、希望職種に合わせた事例数の補強にはなるが、 やはり、伝達構造が変わらなければ根本的な解決にはつながりにくい。
そのため、採用者の評価基準に則ったサイトの再構成ならびに意図・思考プロセスの説明の補完を行う、再定義案が最優先して行うべき作業だと判断した。

04. REASONING

採用者の負担がかからず、自然に伝わる構成へと情報を整理

再定義案を選んだあと、ポートフォリを再構成していく設計では「何を増やすか」ではなく 「どう並べ、どう読まれ、どう理解されるか」を構造的に整理した。

忙しい採用側が短時間で判断しやすいよう、 ポートフォリオTOPを明快にすることから始め、興味の高い順番を意識してコンテンツを配置した。 また制作物も意図したものを見てもらえるよう、こちらで選定した代表プロダクトを軸に、制作物の立ち位置を調整した。

■ 情報を分断せず、文脈の中で理解できる構造へ

TOPでは「どんなデザイナー」なのかを入口で明確にし、見てもらいたい制作物を絞って配置することで、 忙しい採用担当者でも目に留まりやすい構成にしている。 またPROFILEは特定のページ位置へ飛ばすのではなくモーダル表示とすることで、 制作物と行き来しながら文脈の中で理解できる導線にしている。

■ 代表プロダクトの選定自体を、判断材料として再設計

代表プロダクトは単発の制作物として並べるのではなく、 実務 → 応用 → 発信設計の流れとして接続した。 異なる目的を持つ事例でありながらも、 思考プロセスやユーザー視点を大切にした制作の一貫性が読み取れるよう、各プロダクトの説明工程を構造化した。

■ 飛ばし読みでも理解できるテキスト構成

制作物を作成するにあたっての思考プロセスは必須であるものの、どうしても説明のテキスト量が多くなってしまい、忙しい採用担当者に全文を理解してもらうには難しい情報であった。そのため、飛ばし読みでも理解できるよう、要点をタイトルに抽出し、気になった部分を深く読んでもらえるような構成にした。

こうして、選んだ方針を具体的な情報設計と導線設計に落とし込み 「任せられる根拠」が自然に伝わる構造へ整えていった。

05. FINAL DECISION

ポートフォリオ自体を“任せられる根拠を伝えるプロダクト”として再設計

各事例の章構成を揃え、 課題 → 判断 → 制作過程 → UI → 学び の流れが追えるように整理した。 あわせて、自主制作ではあるものの、SaaSプロダクトを“ユーザー体験からの視点”で課題設定からUI制作まで一貫して制作。 実務、応用、そして発信設計という流れで、思考の一貫性や再現性が読み取れる構成へとポートフォリサイトを再定義し、「任せられる根拠」となるプロダクトへ変換した。

05. DESIGN STRUCTURE

実務・自主制作・発信設計をつなぐことで、単発の実績ではなく思考の流れとして見せる

本改善では、各事例を独立した制作物として並べるのではなく、 実務で得た現場理解を起点に、 それをSaaS自主制作でプロダクトとして整理し、 最終的にどう伝えるかをポートフォリオ改善で設計する流れとして整理した。

これにより、 単なるWEB制作経験ではなく、 課題の発見、構造化、プロダクトとしての整理、 そしてアウトプットまで、どのように考えながら一連の制作過程を進めているかが伝わるような構成とした。

また、各代表プロダクトの詳細ページでも章立てを揃えることで、 採用側が比較しながら、 どの事例にも共通する思考の再現性を読み取れる構造へ寄せている。

06. UI DESIGN

採用側の判断スピードを意識し、短時間でも評価項目が追える構造へ整理する

この改善では、見た目を整えること自体ではなく、 「何を見れば任せられると判断できるか」を先に整理し、 その評価項目に沿って読み順・見出し・情報量・ページの接続を設計した。

ポートフォリサイトの構成を再設計

採用者の興味の高さを意識して、TOPでは瞬時に何者かが理解できる簡潔な自己紹介をヒーローに配置し、それを裏付けるような代表プロダクトへとつなげている。
また、PROFILEは特定のページ位置へ飛ばすのではなくモーダル表示とすることで、制作物と行き来しながら文脈の中で理解できる導線にしている。

各代表プロダクトの接続と構造を再設計

採用側が見ている評価項目を起点に、代表プロダクトの構成を見直し、 実務・自主制作・発信を分断せずに配置した。
各事例は個別に完結させるのではなく、 一連の思考の流れとして接続し、 比較しながら理解できる構造に整理している。
また、関係者や担当範囲を補足することで、 個人の成果とチームでの役割が正しく伝わるように整理している。

飛ばし読みでもわかるような文章構成

第一印象で要点が把握できるよう、 概要・見出し・段落・余白・図・強調ラインを調整した。
情報量を減らすのではなく、短い時間でも判断に必要な情報が目に入る構成を優先している。

思考の流れが追えるアンカーリンク

説明ページとしてどうしても長くなってしまうため、採用者が一瞬でページ構成を把握できるようにアンカーリンクを設置。
思考の段階的な流れが分かると共に、気になる箇所にすぐ飛べたり、戻って読んでもらいやすいように設計している。また常時表示するのではなく、スクロールに合わせて表示することで、必要なときに必要な情報が見えるようにしている。

07. IMPLEMENTATION

設計を成立させるための実装

本改善では、構造設計で定義した評価基準と読み順を、 ページ全体に一貫して反映することを重視した。

単に情報を追加するのではなく 「何を見れば判断できるか」を起点に、 各セクションの役割・順序・情報粒度を整理している。

■ 評価基準を、読み順と構造に反映

採用側が見ている担当範囲、課題設定力、要件整理、構造設計、プロダクト理解、アウトプット品質といった評価項目をもとに、 各プロダクトの構成と採用者の読み込み順序を設計した。 課題 → 判断 → 制作過程 → UI → 学び の流れを揃えることで、 個別の成果ではなく、思考の再現性として伝わる構造にしている。

■ 全体を比較しながら読めるよう、一貫性を持たせた

代表プロダクトごとに見出し構成や情報の詳細さを揃え、 読み方を毎回学び直さなくても比較できる状態をつくった。 これにより、採用者のポートフォリサイトの読み込みの負担を軽減し、短時間でも複数の事例を把握しやすくしている。

■ 実務としての再現性が伝わるよう整理

単発の制作物紹介に見えないよう、 各プロダクトでは担当範囲・関係者・意思決定の流れが読み取れる構成にした。 これにより「作ったもの」ではなく、 現場でどのように考え、進め、改善してきたかが伝わるようにしている。

■ 改善スピードと設計の妥当性を両立

制作過程ではAIツールも初期整理や比較検討に活用したが、 そのまま採用するのではなく、最終的な判断は自分で行った。 試行速度を上げつつも、 文脈や強みが薄まらないよう設計の主体を保っている。

このように、設計で定義した内容をページ全体に一貫して反映することで、 ポートフォリオ自体を「任せられる根拠」が自然に伝わる状態へ実装した。

08. EXPECTED IMPACT & RESULTS

書類通過率を上げるために“任せられると判断される状態”を設計する

本改善では、制作物単体の見た目だけではなく、 課題設定、構造設計、プロダクト理解、 改善プロセスの再現性が追いやすい状態を目指した。 その結果、書類選考の段階でも、 これまで伝わりにくかった「任せられる根拠」を示しやすくなる。

また、実務経験と自主制作、そしてそれを伝える設計までを接続したことで、 WEBデザイナー / 通販サイト運用寄りの見え方から、 よりUX / UI・プロダクトデザイナーとしての見え方へ寄せることを意図している。

09. LEARNING

ポートフォリオもまた、採用側の理解行動を前提に設計すべきプロダクトだった

本取り組みは、対象がポートフォリオサイトであったとしても、 課題の特定・仮説の設定・構造の再設計・検証という一連のプロセスを踏むことで、 有効な改善を行うことができることを示す結果となった。

また、採用者というユーザーの視点から、 ポートフォリオの設計や内容を検討する必要があると認識した。 この考え方は、WEBサイトやプロダクトの改善においても 同様に適用できるものだと考えている。
改善後の反応や結果を踏まえながら、引き続き改善を続けていく予定である。
