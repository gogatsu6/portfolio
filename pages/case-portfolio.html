03. CASE STUDY

Portfolio
Redesign.

PROJECT : ポートフォリオ改善 / 情報設計の再構築

ROLE : 情報設計 / UX設計 / UI設計 / 構成再定義 / 実装 / 改善

KEY POINT

転職活動の書類選考を通して見えてきたのは、 作品数や経験年数そのものではなく 「プロダクトデザイナーとして任せられる根拠」が 十分に伝わっていないことだった。
そこで、各企業の募集要項から採用側の不安や評価観点を整理し、 実務 → 自主制作 → 伝達設計という流れで、 代表プロダクト全体の見せ方を再定義した。
ポートフォリオ自体を、思考・判断・再現性を伝えるための プロダクトとして再設計している。
本ページでは、個別の成果ではなく 「どのように課題を捉え、どのように判断し、構造に落としたか」 という一連のプロセスを紹介している。

01. OVERVIEW

BACKGROUND

転職活動の書類選考の中で、実務経験や自主制作はある一方、 プロダクトデザイナーとして「任せられる状態」に 見えていないと感じていた。 特に、課題設定・構造設計・改善プロセスの再現性が、 既存のポートフォリオでは十分に伝わっていなかった。

CORE GOAL

書類通過率を安定して改善し、 UX / UI・プロダクトデザイナー職の面接に進める状態をつくること。 そのために、採用側が短時間で「任せられる」と 判断しやすい構造へ見直すことを目的とした。

TARGET READER

主な対象は、SaaS企業の採用担当者、 UX / プロダクトデザイナー、マネージャーなどの現場メンバー。 あわせて、エージェント担当や書類スクリーニング担当も想定している。

MY APPROACH

問題を単なるポートフォリオ更新ではなく、 採用側の不安を解消するための 情報設計とポジショニングの調整として捉えた。 そのため、画面の見た目だけではなく、 プロジェクトの並び、役割の見せ方、 SaaS自主制作の位置づけまで含めて全体構造から見直している。

WHY THIS PROJECT

転職活動の中でポートフォリオ改善を複数回重ねてきた経験から、 ポートフォリオも一度作って終わりではなく、 読み手の反応を踏まえながら改善を続ける必要があると考えた。
その過程は、課題を捉え直し、 構造や見せ方を更新していくという点で、 プロダクト改善の進め方とも重なる部分があると感じている。
当初は制作物一覧として作成し、 その後は実績ベースで再構成。 さらに、希望職種との距離を埋めるために SaaS自主制作を追加した。
そして今回、それらを単発の実績として並べるのではなく、 実務 → 自主制作 → 伝達設計という 一連の流れとして再定義している。

02. PROBLEM

■ 採用側の3つの不安に対して「任せられる根拠」が十分に伝わっていなかった

各企業の募集要項を整理した結果、 採用側が気にする点は以下の3つにあると仮説立てた。
① SaaS / プロダクト経験がなくても任せられるか
② 改善プロセスに再現性があるか
③ チーム開発の前提で動けるか
 旧ポートフォリオでは、 それらに対する判断材料が構造として見えにくかった。

■ Webデザイナー / EC運用寄りに見え、プロダクトデザイナーとしての見え方にズレがあった

実務経験の見せ方や事例の並び方によって、 UIを作る人・運用を回す人という印象が先に立ちやすく、 課題設定や構造設計まで担える プロダクトデザイナーとしての見え方につながりにくかった。

■ SaaS自主制作が補足的に見え、実務経験からの課題制作として見えていなかった

希望職種との距離を埋めるために制作したSaaS事例も、 位置づけが弱いままでは単なる自主課題として 見られやすい状態だった。
本来は、実務経験を踏まえたユーザー視点から課題を抽出し、 プロダクトとしての価値を整理した成果物である。 しかし、その意図が評価につながりにくかった。

■ 採用側の評価項目に対して、ポートフォリオ全体の構造が最適化されていなかった

採用側は、課題設定力、要件整理、構造設計、プロダクト理解、 チーム前提、判断スピード、アウトプット品質までを短時間で見ている。
しかし従来の構成では、それらを読み取るために解釈が必要であり、 第一印象と判断スピードの面でも不利になっていた。

03. THE INSIGHT

足りなかったのは経験年数ではなく、
“任せられる根拠の見せ方” だった。

本取り組みを通して、 価値は情報量ではなく、 評価の基準と構造の整合によって決まると捉え直した。
スキル・実績・応用といった要素を個別に追加しても、 それぞれが評価の軸と一致していなければ、 意図した価値としては伝わらない。
そのため、情報の内容だけでなく 「誰が・何を基準に・どのように判断するか」を前提に、 構造そのものを設計対象として扱う必要があると考えた。

04. STRATEGIC DECISION

制作物・実績・自主制作と試行を重ねる中で、 問題は情報量ではなく構造にあると捉え直し、 評価基準に合わせて再設計した。

01. PROJECT START

出発点は、評価につながりにくい状況が続いていたことだった

制作物や経験はあるにもかかわらず、 書類選考の段階で評価につながりにくい状況が続いていた。
要因を整理すると、希望職種とのポジショニングのズレ、 制作物の説明構造の不足、採用側の評価基準に沿っていない構成など、 複数の課題が重なっている状態だった。

02. REFRAMING THE ISSUE

制作物・実績・自主制作と試行しても、問題は全体構造にあると分かった

改善は、段階的な検証プロセスとして進めた。 試行ごとに見え方は変わったが、 個別対応では採用側の評価観点とのズレを解消しきれなかった。

STEP 1

制作物一覧として作成

まずは「どんなことができるか」という視点から、 制作物を一覧的に配置した。 スキルの幅は伝えやすくなったが、 プロダクトデザイナーとして任せられる判断材料にはなりにくかった。

↓

STEP 2

実績ベースで再構成

次に「どんなことをしてきたか」「どんな課題に取り組んだか」という視点から、 実績や成果を補足する構成へ切り替えた。 経験の裏付けは強化できたが、 課題設定や構造設計のプロセスまでは十分に伝わらなかった。

↓

STEP 3

SaaS自主制作を追加

さらに、自主制作を通じて応用力の表現を試みた。 希望職種との距離は埋められたが、 既存構造のままでは補足的な事例として見えやすく、 思考のプロセスまで伝えるには不十分だった。

これらの試行を通して、 制作物や実績を追加しても 「どのように考え、どう判断しているか」が ポートフォリオ全体を通して十分に伝わっていないと分かった。

03. DECISION MAKING

複数の改善案を比較し、構造から見直す“再定義案”の方針を選択した

制作物の整理や追加ではなく、 評価基準に対してどう伝わるかを踏まえ、 構造から見直す方針とした。

一覧強化案

既存実績を整理し、見せ方を最適化する

Pros: 工数が少なく短期間で整えられる

Cons: 評価基準とのズレやポジショニングは解消しにくい

再定義案

代表プロダクト全体を再定義し、構造から見直す

Pros: 実務・自主制作・発信を一貫した流れとして接続できる

Cons: 構造整理と意図の説明が必要になる

追加制作案

新規制作を追加し、事例数で補完する

Pros: 事例数を増やし経験の幅を補強できる

Cons: 構造が変わらなければ伝わり方は変わりにくい

一覧強化案は見た目を整えるには有効だったが、 採用側が知りたい「どのように考え、どう判断しているか」までは伝えきれないと考えた。
追加制作案は事例数の補強にはなるが、 伝達構造が変わらなければ根本的な解決にはつながりにくい。
そのため、実務・自主制作・発信設計を一つの流れとして接続し直せる 再定義案が最も適していると判断した。

04. REASONING

選んだ方針を、判断材料が自然に伝わる構造へ具体化した

再定義案を選んだあと、 実際の設計では「何を増やすか」ではなく 「どう並べ、どう読まれ、どう理解されるか」を整理した。

採用側が短時間で判断しやすいよう、 ポートフォリオ全体を一つのプロダクトとして捉え直し、 入口・導線・代表事例の位置づけ・一覧との役割分担まで含めて再設計した。

■ 情報を分断せず、文脈の中で理解できる構造へ

TOPでは「何ができる人なのか」を入口で明確にし、 忙しい採用担当者でも意図を掴みやすいように整理した。 またPROFILEは特定のページ位置へ飛ばすのではなくモーダル表示とすることで、 制作物と行き来しながら文脈の中で理解できる導線にしている。

■ 代表プロダクトの選定自体を、判断材料として再設計

代表プロダクトは単発の制作物として並べるのではなく、 実務 → 応用 → 発信設計の流れとして接続した。 異なる目的を持つ事例でありながらも、 背景にある考え方の一貫性が読み取れるよう整理している。

■ 幅と深さの両方が伝わるよう、全体を再構成

他の作品は一覧で見せて実務の幅を補完し、 代表プロダクトでは思考プロセスまで含めて再構成した。 単なる成果の提示ではなく、 判断の流れが読み取れる形に整理している。

こうして、選んだ方針を具体的な情報設計と導線設計に落とし込み 「任せられる根拠」が自然に伝わる構造へ整えていった。

05. FINAL DECISION

ポートフォリオ自体を、“任せられる根拠を伝えるプロダクト”として再設計する

各事例の章構成を揃え、 課題 → 判断 → 構造 → UI → 学び の流れが追えるように整理した。 あわせて、SaaS自主制作を“ユーザー体験からの視点”で課題設定〜UI制作まで一貫して見せることで、 代表プロダクト全体として思考の再現性が伝わる状態へ再定義した。

05. DESIGN STRUCTURE

実務・自主制作・発信設計をつなぐことで、単発の実績ではなく思考の流れとして見せる

本改善では、各事例を独立した制作物として並べるのではなく、 実務で得た現場理解を起点に、 それをSaaS自主制作でプロダクトとして整理し、 最終的にどう伝えるかをポートフォリオ改善で設計する流れとして整理した。

これにより、単なるWeb制作経験ではなく、 課題の発見、構造化、プロダクトとしての整理、 そしてアウトプットまでの一連の流れが読み取れる構成とした。

また、各代表プロダクトの詳細ページでも章立てを揃えることで、 採用側が比較しながら、 どの事例にも共通する思考の再現性を読み取れる構造へ寄せている。

06. UI DESIGN

採用側の判断スピードを意識し、短時間でも評価項目が追える構造へ整理する

この改善では、見た目を整えること自体ではなく、 「何を見れば任せられると判断できるか」を先に整理し、 その評価項目に沿って読み順・見出し・情報量・ページの接続を設計した。

STRUCTURE DESIGN

採用側が見ている評価項目を起点に、 代表プロダクト全体の読み順と構造を再設計した。
各事例は個別に完結させるのではなく、 一連の思考の流れとして接続し、 比較しながら理解できる構造に整理している。

INFORMATION DESIGN

代表プロダクトの構成を見直し、 実務・自主制作・発信を分断せずに配置した。
また、関係者や担当範囲を補足することで、 個人の成果とチームでの役割が正しく伝わるように整理している。

READABILITY

第一印象で要点が把握できるよう、 見出し・段落・余白・改行位置・ページ順を調整した。
情報量を減らすのではなく、 判断に必要な情報が先に入る構成を優先している。

TRADE-OFFS

情報量 vs 判断しやすさ

実績や背景を多く載せるほど説明量は増えるが、 その分、第一印象の判断スピードは落ちやすい。 そのため本改善では、削ることよりも 「何をどの順番で見せるか」の優先順位で整理する方針を取った。

改善スピード vs 設計の妥当性

AIツールを使えば試行速度は上がる一方で、 そのまま採用すると文脈や強みが薄くなるリスクもある。 そのため、探索は速く、判断は自分で行う分担を明確にしている。

07. IMPLEMENTATION

設計を成立させるための実装

本改善では、構造設計で定義した評価基準と読み順を、 ページ全体に一貫して反映することを重視した。

単に情報を追加するのではなく 「何を見れば判断できるか」を起点に、 各セクションの役割・順序・情報粒度を整理している。

■ 評価基準を、読み順と構造に反映

採用側が見ている課題設定力、構造設計力、プロダクト理解、 判断スピードといった評価項目をもとに、 各プロダクトの構成と読み順を設計した。 課題 → 判断 → 構造 → UI → 学び の流れを揃えることで、 個別の成果ではなく、思考の再現性として伝わる構造にしている。

■ 全体を比較しながら読めるよう、一貫性を持たせた

代表プロダクトごとに見出し構成や情報粒度を揃え、 読み方を毎回学び直さなくても比較できる状態をつくった。 これにより、短時間でも複数の事例を横断しながら、 強みや判断の傾向を把握しやすくしている。

■ 実務としての再現性が伝わるよう整理

単発の制作物紹介に見えないよう、 各プロダクトでは担当範囲・関係者・意思決定の流れが読み取れる構成にした。 これにより「作ったもの」ではなく、 現場でどのように考え、進め、改善してきたかが伝わるようにしている。

■ 改善スピードと設計の妥当性を両立

制作過程ではAIツールも初期整理や比較検討に活用したが、 そのまま採用するのではなく、最終的な判断は自分で行った。 試行速度を上げつつも、 文脈や強みが薄まらないよう設計の主体を保っている。

このように、設計で定義した内容をページ全体に一貫して反映することで、 ポートフォリオ自体を「任せられる根拠」が自然に伝わる状態へ実装した。

08. EXPECTED IMPACT & RESULTS

通過率を上げるために“任せられると判断される状態”を設計する

本改善では、制作物単体の見た目ではなく、 課題設定、構造設計、プロダクト理解、 改善プロセスの再現性が追いやすい状態を目指した。 その結果、書類選考の段階でも、 これまで伝わりにくかった「任せられる根拠」を示しやすくなる。

また、実務経験と自主制作、そしてそれを伝える設計までを接続したことで、 Webデザイナー / EC運用寄りの見え方から、 よりプロダクトデザイナーとしての見え方へ寄せることを意図している。

POSITIONING IMPROVEMENT

SaaS自主制作を補足ではなく主役級の事例として位置づけ直したことで、 希望職種との接続が明確になり、 プロダクト思考や構造設計力を評価されやすい状態へ近づけている。

ONGOING IMPROVEMENT

このページは完成して終わりではなく、 今後の応募結果や面接での反応を踏まえながら改善を続ける前提で設計している。 ポートフォリオ自体を継続的に改善するプロダクトとして運用していく。

09. LEARNING

ポートフォリオもまた、採用側の理解行動を前提に設計すべきプロダクトだった。

本取り組みは、対象が自分自身であっても、 課題の特定・仮説の設定・構造の再設計・検証という一連のプロセスが 有効であることを示す結果となった。

また、価値の伝達はコンテンツ単体ではなく、 構造と評価基準の関係性によって成立するものであると認識している。

この考え方は、Webサイトやプロダクトの改善においても 同様に適用できるものだと考えている。
